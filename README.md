# 삼일핏 (Samil Fit)

다이어트 목표 · 야근 시간 · 식대 버짓을 넣으면 용산 일대 식당과 편의점 메뉴로 1주일 맞춤 식단과 칼로리를 짜주는 앱.
2026 Discover B-4조. **화면 설계서 v0.8** 기준으로 구현.

## 실행 · 배포
```bash
python3 -m http.server 8001 --directory samil-fit
```
- `index.html` 하나(CSS·JS 포함) + `data/restaurants.json`. 빌드 없음. 이 폴더를 저장소 루트로 두면 Vercel에 그대로 배포됨.
- `file://`로 직접 열면 JSON을 불러오지 못하니 http 서버로 열 것.

## 화면 (10/06 리뷰 반영: 2단계)
| 화면 | 주소 | 내용 |
|---|---|---|
| 1. 조건 입력 | `#setup` (첫 화면) | 점심 · 저녁 · 야식 버짓, 예산 활용, 식단 상태(직접 입력 포함), 요일별 근무 형태, 야식 여부, 치팅·회식 끼니(최대 3) · 치팅 칼로리 → [이번 주 식단 짜기] |
| 2. 이번 주 식단 | `#plan` | 맨 위 '내 조건' 요약 + [조건 수정], 월~금 식단표, [식단 다시 짜기], 메뉴 제보하기(구글 폼), 주간 영양 리포트 · 식비 예측 |
| 메뉴 상세 시트 | 카드 클릭 | 아래에서 올라옴 · 메뉴 정보 · 비고 · 다른 메뉴로 바꾸기 |

- 조건 입력 화면에서 바꾼 값은 [식단 짜기]를 눌러야 반영됨 (설계서의 '즉시 재계산'에서 변경, 팀 리뷰 결정).
- 디자인: **라이트 모드 전용**. 참고 이미지 색 — 분홍 #FFE0E6 · 복숭아 #FFD4C2 · 코랄 #FCAE8C 그라데이션 → 흰색, 검정 글씨, 주황 #FD5108 포인트 (로고 · 브랜드 마크는 사용 안 함).

## 데이터 (`data/restaurants.json`)
설계서 5-1 형식, 메뉴 1개 = 객체 1개.
```json
{ "id": "...", "restaurant": "...", "area": "ls|yr|ipark|cvs", "menu": "...", "price": 12900,
  "kcal": 650, "source": "official|est", "open": { "lunch": true, "dinner": true, "late": false },
  "carb": null, "protein": null, "fat": null, "note": "일요일 휴무", "added": "2026-10-05" }
```
- `added`: 변환 스크립트가 이전 데이터에 없던 메뉴(식당명+메뉴명 기준)에만 그날 날짜(KST)를 붙임. 앱은 가장 최근 날짜의 메뉴를 상단 'NEW' 배너로 14일간 보여줌(✕로 닫으면 그 업데이트는 다시 안 뜸). 식당 메뉴가 전부 새것이면 '새 식당'으로 표시. 메뉴명을 바꾸면 새 메뉴로 잡힘.
- `note`: 엑셀 '비고' 칸. S3 메뉴 상세 시트에 📝 한 줄로 표시 (설계서 추가 항목, 팀 합의).
- 원본 엑셀: `data/menu.xlsx` (첫 번째 시트만 사용, 다른 시트는 무시). 현재 52곳 · 127개 메뉴.

## 메뉴 데이터 업데이트 (데이터팀용)
사용자 제보는 앱의 "메뉴 제보하기" → [구글 폼](https://docs.google.com/forms/d/e/1FAIpQLSeQ0JX40fYWNZvibPIMkDMBatAE-K-me1dcSiktMiRDEwXa4A/viewform)으로 들어옴 → 데이터팀이 확인 후 엑셀에 추가.

1. 엑셀 첫 번째 시트에 행 추가 · 수정 (열 순서 · 제목은 그대로, 영업 여부는 O/X, 출처는 공식값/추정치)
2. 파일 이름을 **`menu.xlsx`** 로 저장
3. GitHub 저장소 → `data` 폴더 → **Add file → Upload files** → `menu.xlsx` 끌어다 놓기 → **Commit changes**
4. **Actions** 탭에서 "메뉴 데이터 반영"이 ✅ 이면 끝 (1~2분 뒤 앱에 반영)
   - ❌ 이면 실패 로그에 "N행 식당 / 메뉴: 이유"가 나옴 → 엑셀 고쳐서 다시 업로드. 고치기 전까지 앱은 이전 데이터 그대로

- 구글 폼 구역 선택지('AP 본사 B1')처럼 띄어쓰기만 다른 값은 그대로 붙여 넣어도 됨.
- 새 구역 이름을 쓰려면 `tools/xlsx_to_json.py`의 `AREA` 표에 추가해야 함 (빌드팀에 요청).
- 로컬에서 미리 확인: `python3 tools/xlsx_to_json.py` (기본값 data/menu.xlsx)

## 설계서에 없던 부분 — 팀 확인 후 결정한 것 (10/03)
- 치팅 끼니 목표 칼로리: 기본 **800 kcal**, 10/07부터 사용자가 400~1,500 설정. 버짓은 일반 끼니와 같음.
- 칼퇴인 날 저녁을 치팅 끼니로 고르면 **치팅 저녁을 추천**함 (저녁 식대 버짓, 구역 제한 없음, 하루 목표·주간 버짓에 포함).
- 주간 버짓 = 점심 버짓 × 5 + 저녁 버짓 × (저녁을 추천하는 날 수) + 야식 버짓 × (야식 추천 날 수). (10/07 야식 버짓 분리하면서 야식도 포함)

## 크로스 피드백 반영 (10/07, A-5조 · 내부 리뷰 · 피드백 문서)
| 반영 | 내용 |
|---|---|
| 뒤로가기 | 메뉴 상세를 연 상태의 뒤로가기는 상세만 닫음 (첫 화면으로 튕기던 문제) |
| 메뉴 교체 안내 | 식단표 위 안내 + 카드마다 '바꾸기 ›' |
| 메뉴 반복 안내 | 예산 · 영업시간 탓에 같은 메뉴가 반복되면 이유 한 줄 |
| 데이터 기준 | "2026년 10월 조사 기준, 실제와 다를 수 있음" |
| 버짓 입력 | 쉼표 표시(15,000), 점심 / 저녁 / 야식으로 용어 통일 |
| 범례 · 그래프 | 탄단지 색 설명, 요일별 칼로리 그래프에 '저녁 자율' 표시 |
| 치팅 · 회식 끼니 | 월~금 × 점심/저녁 중 최대 3끼 자유 선택, 치팅 칼로리 400~1,500 설정 (기존: 3개 중 1개, 800 고정) |
| 칼로리 직접 입력 | 식단 상태에 '직접 입력'(끼니당 300~1,500 kcal, 벌크업 포함). 야식 목표는 끼니 목표 800 이상이면 500, 아니면 300 |
| 야식 | 심야 야근 날 야식 추천 여부 선택, 야식 버짓 별도(기본 8,000원). 주간 버짓에 야식 버짓 × 야식 날 수 포함 |
| 예산 활용 | '아껴 쓰기'(기본, 싼 메뉴 약간 우대) / '버짓에 가깝게'(버짓보다 많이 싼 메뉴 감점). 타이트 모드 10회 평균: 끼니 가격 6.4천 → 12.8천원, 편의점 비중 50% → 10% |
| 데이터 반영 | 엑셀 업로드 직후 바로 보이게 데이터 캐시 끔 |

보류 (확장 방향): 메뉴 교체 시 다른 끼니 권장량 자동 조정, 영양 선호(고단백 등), 요일별 식단 상태 · 예산, 예산 범위, 못 먹는 음식 · 선호 카테고리, 아침 식단, 지도 연결(외부 API 금지).
